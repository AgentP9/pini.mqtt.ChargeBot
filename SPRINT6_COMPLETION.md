# Sprint 6 — Intelligent completion detection

The first increment introduces a **read-only** completion assessment that
explains why a charging session is or is not considered complete.

Endpoint: `GET /api/chargers/:chargerId/completion-assessment`.

It returns an `assessment` with `ready`, `reason`, and optional sample
metadata, plus a `comparison` against the existing detector. The Diagnostics
tab shows the evidence and highlights when the detectors disagree. Reasons include `insufficient_samples`,
`insufficient_window_coverage`, `telemetry_stale`, `telemetry_gap`,
`power_above_threshold`, `rising_power_trend`, and `stable_low_power`.

**Safety:** This endpoint is advisory-only. It does not change existing
automatic shutdown decisions. Any future rollout into auto-off requires
fixture parity, negative-case tests, and a separately reviewed opt-in.

Next increments: build realistic replay fixtures, compare the existing detector
against the new assessment, add operator-visible evidence and controlled
rollout criteria.

## Replay safety gate

`tests/test-completion-replay-matrix.js` exercises twelve deterministic
synthetic charging traces, including steady completion, active charging,
transient spikes, negative readings, threshold boundary, telemetry outage,
stale/future data, too few samples, out-of-order data, duplicate timestamps,
and resumed charging. CI requires both detectors to agree on every fixture
and explicitly rejects false positives on known negative traces.

This is a **synthetic parity gate**, not proof of safety on real hardware.
Before enabling the new assessment for automatic shutdown, replay anonymized
production traces and test MQTT disconnects, relay confirmation and delayed
telemetry in an isolated test environment. The production auto-off decision
continues to use the existing detector.

## Offline replay of real-world charging traces

Export **anonymized** traces locally (do not commit raw logs, MQTT topics,
device names, IP addresses or personal timestamps). Supply a JSON array:

```json
[
  {
    "expectedReady": false,
    "evaluationTime": "2026-11-08T12:00:00Z",
    "samples": [
      {"timestamp": "2026-11-08T11:40:00Z", "watts": 35},
      {"timestamp": "2026-11-08T12:00:00Z", "watts": 35}
    ]
  }
]
```

Use a full sequence of at least 20 samples over the relevant window for
meaningful completion assessment. `expectedReady` must be manually labeled
from independent evidence, **not** generated by either detector. Run:

```sh
node backend/replay-real-traces.js /private/path/anonymized-traces.json
```

The command reports disagreements, false positives and false negatives;
returns nonzero for disagreement or false positive. It reads the file locally
without sending samples to a server. CI tests the replay harness with
synthetic examples; **no real charging traces have been supplied or tested yet**.

## Export existing ChargeBot history locally

The backend already persists charging sessions and serves them at
`GET /api/processes`. Obtain the JSON only within your trusted network
and store it locally. It contains sensitive raw history; **do not commit it**.

```sh
node backend/export-process-replays.js /private/processes.json /private/replay-candidates.json
```

The export excludes appliance sessions and active charging sessions by
default, retains only timestamp/power samples, shifts timestamps to a fixed
synthetic date while preserving intervals, and strips device identifiers and
names. The output file is created with owner-only permissions and will not
overwrite an existing file. `--include-active` explicitly opts into active
sessions. Candidates with fewer than 20 valid samples are skipped.

**Manual ground truth is required:** each exported candidate has
`"expectedReady": null`. Review the trace using independent evidence
(e.g. known charge status or verified end-of-charge), then set this to
`true` or `false`. Do not infer ground truth from the existing detector or
the fact that a process has an end time. The replay runner rejects unlabeled
candidates. Evaluate only at the exported `evaluationTime`; a finished
session may have been switched off manually.

```sh
node backend/replay-real-traces.js /private/verified-replays.json
```

**No production data has been retrieved or exported by this change.**
